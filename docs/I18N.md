## Overview

The application uses a **custom i18n system** (no external library) with:

- **Two languages**: German (de) and English (en)
- **Default language**: German (de)
- **Persistence**: localStorage (`bl-locale`)
- **Type safety**: Full TypeScript support with dot-notation keys
- **Fallback**: Missing keys fall back to German

### Why Custom i18n?

**Decision**: Use custom i18n hook instead of i18next

**Reason**:
- Lightweight (no external dependencies)
- Full TypeScript support with autocomplete
- Simple dot-notation key access
- No provider setup required
- Zustand integration for language switching

**Trade-offs**:
- No pluralization support (not needed for this app)
- No interpolation (use template literals instead)
- No lazy loading (all translations loaded upfront)

## Translation System

### Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    Translation System                        │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │ languageStore│  │ useTranslation│  │ Translation  │      │
│  │              │  │     Hook      │  │    Files     │      │
│  │ • locale     │  │              │  │              │      │
│  │ • setLocale()│  │ • t(key)     │  │ • de.ts      │      │
│  │              │  │ • locale     │  │ • en.ts      │      │
│  │ (persisted)  │  │              │  │              │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
│         ↓                  ↓                  ↓              │
│         └──────────────────┴──────────────────┘              │
│                            ↓                                 │
│                   Component renders                          │
│                   translated text                            │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

### Data Flow

```
User clicks language button
    ↓
languageStore.setLocale('en')
    ↓
localStorage.setItem('bl-locale', 'en')
    ↓
Components using useTranslation() re-render
    ↓
t(key) returns English string
```

## useTranslation Hook

**Location**: `src/live-predict/hooks/useTranslation.ts`

Custom hook for accessing translations.

### API

```typescript
function useTranslation(): {
  t: (key: TranslationKey) => string;
  locale: Locale;
}
```

### Usage

```typescript
import { useTranslation } from '@/hooks/useTranslation';

function LoginPage() {
  const { t, locale } = useTranslation();

  return (
    <div>
      <h1>{t('auth.login.title')}</h1>
      <p>{t('auth.login.subtitle')}</p>
      <button>{t('auth.login.submitButton')}</button>
    </div>
  );
}
```

### Type Safety

The hook provides full TypeScript autocomplete for all translation keys:

```typescript
t('auth.login.title')        // ✅ Valid key
t('auth.login.invalidKey')   // ❌ TypeScript error
```

### Fallback Behavior

If a key is missing in the active locale, it falls back to German:

```typescript
// en.ts is missing 'newFeature.title'
t('newFeature.title')  // Returns German string from de.ts
```

If the key is missing in both locales, it returns the key itself:

```typescript
t('missing.key')  // Returns 'missing.key' (for debugging)
```

## Adding a New Language

To add a new language (e.g., Spanish):

### 1. Create Translation File

Create `src/live-predict/i18n/es.ts`:

```typescript
export const es = {
  auth: {
    login: {
      title: 'Iniciar sesión',
      subtitle: 'Inicia sesión para usar Live Predict.',
      // ... (copy all keys from de.ts or en.ts)
    },
    // ...
  },
  // ... (all other keys)
} as const;
```

### 2. Update Locale Type

Update `src/live-predict/store/languageStore.ts`:

```typescript
// Before
export type Locale = 'en' | 'de';

// After
export type Locale = 'en' | 'de' | 'es';
```

### 3. Update useTranslation Hook

Update `src/live-predict/hooks/useTranslation.ts`:

```typescript
import { de } from '../i18n/de';
import { en } from '../i18n/en';
import { es } from '../i18n/es';  // Add import

export function useTranslation() {
  const { locale } = useLanguageStore();

  const t = (key: TranslationKey): string => {
    // Add Spanish to translations map
    const translations = locale === 'en' ? en : locale === 'es' ? es : de;
    const fallbackTranslations = de;

    // ... (rest of implementation)
  };

  return { t, locale };
}
```

### 4. Update LanguageSwitcher

Update `src/live-predict/components/ui/LanguageSwitcher.tsx`:

```typescript
<button onClick={() => setLocale('de')}>DE</button>
<button onClick={() => setLocale('en')}>EN</button>
<button onClick={() => setLocale('es')}>ES</button>  {/* Add button */}
```

### 5. Update localStorage Default

Update `src/live-predict/store/languageStore.ts`:

```typescript
const getInitialLocale = (): Locale => {
  if (typeof window === 'undefined') return 'de';
  
  const stored = localStorage.getItem('bl-locale');
  if (stored === 'en' || stored === 'de' || stored === 'es') {  // Add 'es'
    return stored;
  }
  return 'de';
};
```

## Language Switching

### How It Works

1. User clicks language button in `LanguageSwitcher`
2. `languageStore.setLocale('en')` is called
3. Locale is persisted to `localStorage` under key `'bl-locale'`
4. All components using `useTranslation()` re-render with new translations

### LanguageSwitcher Component

**Location**: `src/live-predict/components/ui/LanguageSwitcher.tsx`

```typescript
import { useLanguageStore } from '@/store/languageStore';

export function LanguageSwitcher() {
  const { locale, setLocale } = useLanguageStore();

  return (
    <div>
      <button
        onClick={() => setLocale('de')}
        className={locale === 'de' ? 'active' : ''}
      >
        DE
      </button>
      <button
        onClick={() => setLocale('en')}
        className={locale === 'en' ? 'active' : ''}
      >
        EN
      </button>
    </div>
  );
}
```

### Persistence

The selected language is persisted in `localStorage`:

```typescript
// Read on app load
const stored = localStorage.getItem('bl-locale'); // 'en' | 'de'

// Write on change
localStorage.setItem('bl-locale', 'en');
```

**Default**: `'de'` (German)

## Best Practices

### 1. Use Dot Notation for Nested Keys

```typescript
// ✅ Good: Organized by feature
auth: {
  login: {
    title: 'Anmelden',
    subtitle: 'Melde dich an...',
  },
}

// ❌ Bad: Flat structure
authLoginTitle: 'Anmelden',
authLoginSubtitle: 'Melde dich an...',
```

### 2. Keep Keys Consistent Across Languages

```typescript
// ✅ Good: Same keys in both files
de: { auth: { login: { title: 'Anmelden' } } }
en: { auth: { login: { title: 'Sign In' } } }

// ❌ Bad: Different keys
de: { auth: { login: { title: 'Anmelden' } } }
en: { auth: { login: { heading: 'Sign In' } } }  // ❌ Different key
```

### 3. Use Template Literals for Dynamic Content

```typescript
// ✅ Good: Use template literals in component
const { t } = useTranslation();
const message = `${t('welcome')} ${userName}!`;

// ❌ Bad: Try to interpolate in translation file
welcome: 'Willkommen {userName}!',  // ❌ No interpolation support
```

### 4. Extract t() at Component Top

```typescript
// ✅ Good: Extract at top
function LoginPage() {
  const { t } = useTranslation();
  
  return <h1>{t('auth.login.title')}</h1>;
}

// ❌ Bad: Call useTranslation() multiple times
function LoginPage() {
  return (
    <div>
      <h1>{useTranslation().t('auth.login.title')}</h1>
      <p>{useTranslation().t('auth.login.subtitle')}</p>
    </div>
  );
}
```

### 5. Use Descriptive Key Names

```typescript
// ✅ Good: Descriptive key names
betSlipConfirm: 'Wette bestätigen',
betSlipCancel: 'Abbrechen',

// ❌ Bad: Generic key names
button1: 'Wette bestätigen',
button2: 'Abbrechen',
```

### 6. Group Related Keys

```typescript
// ✅ Good: Grouped by feature
auth: {
  login: { /* ... */ },
  register: { /* ... */ },
  confirm: { /* ... */ },
}

// ❌ Bad: Scattered keys
loginTitle: 'Anmelden',
registerTitle: 'Registrieren',
loginButton: 'Anmelden',
registerButton: 'Registrieren',
```

### 7. Use `as const` for Type Safety

```typescript
// ✅ Good: Use 'as const' for literal types
export const de = {
  auth: { /* ... */ },
} as const;

// ❌ Bad: No 'as const'
export const de = {
  auth: { /* ... */ },
};
```

## Testing Translations

### Unit Tests

Test that components render correct translations:

```typescript
import { render, screen } from '@testing-library/react';
import { useLanguageStore } from '@/store/languageStore';
import LoginPage from './LoginPage';

test('renders German title by default', () => {
  render(<LoginPage />);
  expect(screen.getByText('Anmelden')).toBeInTheDocument();
});

test('renders English title when locale is en', () => {
  useLanguageStore.setState({ locale: 'en' });
  render(<LoginPage />);
  expect(screen.getByText('Sign In')).toBeInTheDocument();
});
```

### Integration Tests

Test language switching:

```typescript
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import LanguageSwitcher from './LanguageSwitcher';
import LoginPage from './LoginPage';

test('switches language when button is clicked', async () => {
  const user = userEvent.setup();
  
  render(
    <>
      <LanguageSwitcher />
      <LoginPage />
    </>
  );

  // Default: German
  expect(screen.getByText('Anmelden')).toBeInTheDocument();

  // Click EN button
  await user.click(screen.getByText('EN'));

  // Now: English
  expect(screen.getByText('Sign In')).toBeInTheDocument();
});
```

## Troubleshooting

### Missing Translation Key

**Problem**: Key is missing in one language file

**Solution**: Add the key to both `de.ts` and `en.ts`

```typescript
// de.ts
newFeature: { title: 'Neue Funktion' }

// en.ts
newFeature: { title: 'New Feature' }
```

### TypeScript Error: Key Not Found

**Problem**: TypeScript complains about invalid key

**Solution**: Ensure the key exists in `de.ts` (the source of truth for types)

```typescript
// ❌ Bad: Key only in en.ts
en: { newFeature: { title: 'New Feature' } }

// ✅ Good: Key in both files
de: { newFeature: { title: 'Neue Funktion' } }
en: { newFeature: { title: 'New Feature' } }
```

### Language Not Persisting

**Problem**: Language resets to German on page reload

**Solution**: Check that `localStorage` is working:

```typescript
// Debug: Check localStorage
console.log(localStorage.getItem('bl-locale'));

// Should return: 'en' or 'de'
```
